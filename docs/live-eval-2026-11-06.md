# First live run: what the real model did

*2026-11-06 · generate `gpt-5.5-2026-04-23` · gate `gpt-5.4-mini-2026-03-17` · reports in `evals/reports/live-2026-11-06*`*

Until today the pipeline had only run on a deterministic mock. This is the first run against real models: 28 questions on 11 full FDA labels, each answered three times as a pharmacist, plus the support check on the seeded claims.

## Results across three rounds

| Measure | Round A | Round B | Round C (final config) |
| --- | --- | --- | --- |
| Answerable runs producing an answer | 92% | 97% | **99%** |
| Answerable runs citing an expected section | 92% | 97% | **99%** |
| Ungrounded claims shown (GM-01, target 0) | 0 | 0 | **0** |
| Claims dropped as "wrong section" | 14 | 0 | 0 |
| Run-to-run agreement on cited sections | 86% | 86% | 90% |
| Support check verdicts correct | 7 of 8 | 8 of 9 | 8 of 9 |
| Median latency per answer | 9.3 s | 11.2 s | 11.1 s |

The guardrail held from the first call: no claim whose quote isn't in its cited section ever reached an answer. What changed between rounds was how many good answers survived.

## What we found and changed

1. **The answer model rejects temperature 0.** `gpt-5.5` accepts only its default, so the config now allows "model default", and variation is measured instead of assumed away. Cited sections agree 90% of the time across runs.
2. **The model sometimes copied the whole heading as the section code** ("8.1 Pregnancy Risk Summary" instead of "8.1"). The checker correctly dropped every such claim, which turned a good pregnancy answer into "the label doesn't say". Fix: the reply schema now lists the excerpts' exact codes, so strict structured output can't return anything else. Wrong-section drops went from 14 to 0.
3. **The support check flipped on a borderline claim.** "Stop if transaminases exceed three times normal" was judged unsupported once and supported once. The label says "discontinue *or reduce dose*", so the right verdict is unsupported, and our own eval expectation had been too lenient. We corrected the case, added its faithful version, and added a general rule to the support prompt: a claim must not drop a condition, alternative or qualifier. That example was first written into the prompt, then removed, because a prompt that contains the test case proves nothing. With only the general rule, the verdict was right 5 times out of 5.
4. **A stricter gate has a price.** In the final round the support check rejected one faithful Boxed Warning claim. That fails safe (a true claim was dropped, not a false one shown), but it costs answers. We stopped tuning here: more prompt edits against nine claims would be fitting the test, not improving the check.
5. **Short label sentences are real.** "Keep tightly closed." was rejected as too short to quote. The minimum is now three words; "fatal cases" is still rejected.

## Not solved yet: personal advice (M3)

Asked "can I keep taking it now that I'm pregnant?", the model once replied "No — the boxed warning says lisinopril should be discontinued as soon as pregnancy is detected." Every word is grounded in the label, and it is still the wrong answer: Label Lens should state what the label says and send the person to their prescriber, not answer the personal question. The claim checker can't catch this, because nothing in it is unsupported. This is exactly why the safety classifier sits **before** retrieval in the design, and it is the first thing M3 builds.

## Cost and speed

About 115k input and 49k output tokens for 84 answers, plus about 89k and 13k for 259 support checks: roughly 1,400 input and 580 output tokens per answer for generation. The median answer takes 11 seconds, mostly generation. Caching repeated demo questions (architecture 5.5) and a faster generation model are the levers if that's too slow for the demo.

## Caveats

- Nine support-check claims and 28 questions are a small sample, written by the same person who built the system. Questions written by someone who hasn't seen the code are needed before M4.
- Two of the support-check claims resemble the prompt's original examples, so CC-13 is the only clean test of the new rule.
- Only the pharmacist role was run live.
